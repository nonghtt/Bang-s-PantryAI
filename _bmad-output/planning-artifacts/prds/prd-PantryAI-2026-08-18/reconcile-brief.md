# 입력 대조 — 브리프가 말한 것 중 PRD가 떨어뜨리거나 뒤집거나 약화한 것

## 0. 범위와 방법

- 원천 두 파일과 대상 두 파일을 전문 대조했다. 사전 추출본(`extract-brief.md`)은 체크리스트로만 썼고 인용은 원문에서 다시 확인했다.
- **PRD §6.3이 명시적으로 뒤집은 8항목은 제외했다** — 정밀도 층위 분리 → 유무만, 차감·검수 → 소진 판정, 인분 스케일링 소멸, 원본 표기 병기 → 표준명 통일, 커버리지 목표 100건 폐기, 카테고리 추정 → 실측, 729종 → 1,966종, 기준선 127건 강등. PRD가 `[NOTE FOR PM]`·`[ASSUMPTION]`·§8 열린 질문으로 인지한 것도 제외했다.
- 판정에 필요한 사실 세 가지는 저장소에서 직접 확인했다.
  - `scripts/measure_coverage.py`는 **도달 가능 = 완전 매칭 + 1개 부족**으로 센다 (실행 결과: 병합 1,689건 중 완전 6 · 1개 부족 71 → 77건 4.6%).
  - `data/processed/recipes.json`의 `rcp_pat2` 실제 값: 반찬 574 · **일품 181** · 후식 142 · 밥 119 · 국&찌개 103 · **기타 37**.
  - `data/labels/category_answers.csv` 120행, `pantry_assumption.txt` 존재.

분류: **(a) 누락** — PRD에 대응물이 없고 §6.3에도 없음 / **(b) 미인지 모순** — PRD가 브리프와 다르게 말하면서 뒤집었다고 적지 않음 / **(c) 수치 불일치** — 설명 없이 값이 다름.

## 1. (a) 누락 — 브리프에는 있고 PRD에는 대응물이 없는 것

### G-01 · 미사용 재료가 추천으로 이어지는 진입점 — **high**

**브리프** [§Success Criteria › 제품 성공의 정의 · 이 정의가 설계에 강제하는 것]
> "**재료별 사용 횟수의 뒷면이 더 중요하다.** 사용 횟수 0인 재료는 **아직 안 쓴 재료이자 썩을 위험에 있는 재료**다. … 그래서 이 지표는 회고 화면에서 그대로 기능이 된다."
> ```
> "3주간 12가지를 만들었어요"
> "대파 5번 · 계란 4번 · 김치 3번 썼네요"
> "두부는 아직 한 번도 안 썼어요"     ← 추천으로 이어지는 지점
> ```
> "**회고 화면이 곧 지표 화면이다** — 서로 다른 요리 수와 재료별 사용 횟수를 그대로 보여준다. **미사용 재료를 짚어주는 것이 추천으로 이어지는 진입점**이 된다"

**PRD 현재** — SM-2 정의에 "0회 재료 = 썩을 위험 재료, 낭비의 대리 신호"로 **지표로만** 남았다. 화면에는 없다. FR-22 통계 탭(2차)의 항목은 "가장 많이 사용한 재료 · 가장 많이 해먹은 요리 계통 · 선호도"로, **서로 다른 요리 수(SM-1)도, 미사용 재료(SM-2의 뒷면)도 없다.** FR-22가 "성공 지표(§7 SM-1·SM-2)를 화면으로 보이는 자리"라고 자기 소개하지만 열거된 항목이 그 지표와 맞지 않는다. 회고 → 추천 진입점을 정의한 FR은 1차·2차 어디에도 없다. FR-24(등록 후 경과일 가중)가 유무 모델에서 가장 가까운 대체물이지만 회고 화면과 연결되지 않는다.

**착지** — FR-22 항목에 "서로 다른 요리 수"와 "아직 한 번도 안 쓴 재고 재료"를 추가하고, 미사용 재료 항목에서 추천(FR-19/FR-24)으로 들어가는 진입점을 한 줄로 명시한다. 1차 최소 회고를 유지하는 결정은 그대로 두되, 브리프의 회고 예시 문구 세 줄을 FR-22의 목표 화면으로 인용한다.

### G-02 · 시드 데이터로 성능을 증명한다 — **high**

**브리프** [addendum §5 › 실무 강점을 사용자 없이 증명하는 방법]
> "농림부에서 **150만 건 시드 데이터로 부하를 검증**한 전례가 있다. 같은 수법을 적용해 레시피·가상 사용자 재고 이력을 시딩하면 '사용자가 없어서 성능을 말할 수 없다'는 변명이 필요 없어진다."
> [addendum §5 › 서명 강점] "성능 최적화(1,400ms→10ms) · 동시성/정합성 … · 관측 기반 진단"

**PRD 현재** — 성능·부하에 관한 요구가 없다. NFR-12는 LLM 비용만 다루고 "지연은 아키텍처에서 예산으로 정한다"로 넘긴다. 시딩은 어디에도 없다. §7.1 기술 증명 지표 5개는 전부 정확도 축이고 성능 축이 없다. CLAUDE.md가 "관측·정합성·정량 검증은 이 개발자의 실무 서명 강점(1,400ms→10ms, 잔차 0 대조)과 직결"이라고 한 것과 어긋난다.

**착지** — §10에 NFR-14(성능 측정: 가상 사용자·재고 이력 시딩으로 추천 응답·재고 갱신 지연을 측정하고 개선 전후를 비교)를 추가하고, §7.1에 SM-T5(성능 — 미측정)를 둔다. 시딩 규모·대상 테이블은 PRD addendum §1 인계 표로.

### G-03 · 추천 근거 추적 — **medium**

**브리프** [§What Makes This Different › 3. 정확성을 증명하는 설계]
> "재고 정합성, **추천 근거 추적**, 영양 수치의 출처 관리 — '동작한다'가 아니라 **'얼마나 맞는지 측정된다'**를 목표로 한다."

**PRD 현재** — 세 항목 중 재고 정합성만 FR로 살았다. 추천이 **왜** 나왔는지(어느 재고 항목이 매칭됐고, 어떤 필터를 통과했고, 어느 재고 스냅샷 기준인지)를 보여주거나 기록하는 요구가 없다. FR-10 색상 표시는 "없는 재료"만 보이고 근거는 아니다. UJ-4 엣지가 "미탐은 정답 세트와 커버리지 측정으로만 잡힌다"고 했는데, 추천 시점의 재고 스냅샷과 적용 규칙이 기록되지 않으면 그 오프라인 측정을 재현할 수 없다.

**착지** — FR-6 결과에 "추천 결과마다 매칭된 재고 표준명·적용 필터(계통·최근 제외·면제)·재고 스냅샷 식별자를 기록한다"를 추가하거나 §10 NFR로 "추천은 재현 가능해야 한다"를 둔다. 화면 노출 여부는 UX로.

### G-04 · 수집 파이프라인의 건수 검증·재시도 — **medium**

**브리프** [§데이터 › 확인된 제약 · §미해결 항목 › 데이터]
> "**API 응답이 불안정하다** — 식약처 API가 156건 요청에 5건만 반환한 사례가 있었고 재시도로 정상화됐다. **수집 파이프라인에 건수 검증과 재시도가 필요하다**"

**PRD 현재** — FR-15는 "1회성 배치로 수집"이라고만 말한다. NFR-7 잔차 0은 **정제** 단계의 항등식이고 수집 단계의 `totalCnt` 대조·재시도는 어디에도 없다. §8-13(고아 38건 재수집 여부)이 열려 있으므로 수집은 아직 "끝난 일"이 아니다.

**착지** — FR-15 결과에 "수집은 응답 `totalCnt`와 적재 행 수를 대조하고 어긋나면 재시도한다"를 추가.

### G-05 · 두 소스 병합 시 중복 판정 기준 — **medium**

**브리프** [§데이터 › 레시피 코퍼스 후보 · 확인된 제약 · §미해결 항목]
> "**병합 후 이름 기준 고유 1,661종** (이름 완전 일치 중복 14건: 잡채·닭강정·안심스테이크·연어샐러드 등)."
> "**중복 판정 기준이 필요하다** — 이름 완전 일치가 14건이지만 같은 요리가 다른 이름으로 존재할 수 있다. 이름만으로는 부족하고 재료 집합을 함께 봐야 한다"

**PRD 현재** — 코퍼스를 1,693건으로 세고 중복을 언급하지 않는다. §8 열린 질문 17개에 중복 판정이 없다. 이것은 지표에 직접 닿는다 — 같은 요리가 두 ID로 있으면 SM-1(서로 다른 요리 수)이 과대되고, FR-8(최근 조리 제외)이 한쪽만 제외한다.

**착지** — §8에 열린 질문 추가, FR-15 결과에 "중복 처리 정책(유지·병합·대표 선택)"을 둔다.

### G-06 · React로 무엇을 증명할 것인가 — **medium**

**브리프** [§미해결 항목 › 기술 · addendum §6 › 그 밖에]
> "React로 무엇을 증명할 것인가 (스트리밍 UI · 낙관적 업데이트 · 취소·에러 복구)"
> "React 상태관리 및 스트리밍 UI 처리"

**PRD 현재** — §6.1 "여기서 LLM API · RAG · React · 실배포 · 정량 검증이 증명된다"로 이름만 남았다. PRD addendum §1 인계 표에도 없다. 특히 **스트리밍 UI는 추천 생성이 실행 시점 LLM 호출인지에 종속**되는데(§4.3 기능 NFR이 이를 아키텍처로 넘김) 이 의존을 아무 문서도 적지 않았다. 낙관적 업데이트는 FR-1("켜면 즉시 재고에 반영, 별도 저장 버튼 없음")·FR-12 소진 칩과 바로 맞물리는데 연결이 없다.

**착지** — PRD addendum §1 인계 표에 한 행 추가: "React 증명 후보 — 낙관적 업데이트(FR-1·FR-12), 스트리밍(추천 생성 LLM 여부에 종속), 취소·에러 복구(FR-9 승인 교체)".

### G-07 · "추천 밖 소비가 주 경로" 전제와 오차의 방향 — **medium**

**브리프** [§Who This Serves · §The Solution › 세 장치]
> "**핵심 리스크: 루프가 자주 돌지 않는다** — … **추천 밖 소비가 예외가 아니라 주 경로일 수 있다.** 이 전제 위에서 설계해야 한다"
> "추천을 따르지 않은 소비 … 가 전부 누락되어, 시스템은 항상 **실제보다 재고를 많게 믿는 방향**으로 어긋난다."

**PRD 현재** — §5 "추천 밖 소비를 1차에서 추적하지 않는다"로 자르고 FR-20을 2차에 두었다(이것은 인지된 이연). 빠진 것은 둘이다. ① 1차에서 추천 밖 소비를 회수하는 유일한 경로는 **FR-4의 수동 끄기**인데 그렇게 명시되지 않았다. ② §6.2가 "유무 모델에서 오차 누적 속도가 느려 1차 생존 가능"이라고 썼는데 **근거가 없다** — 유무 모델에서 오차는 '항목이 다 떨어졌는데 켜져 있음' 한 방향으로만 쌓이고, 브리프가 말한 편향의 방향과 정확히 같다. 이 주장은 PRD 어디에서도 `[미검증]`으로 표시되지 않았다(NFR-8 위반).

**착지** — FR-4에 "추천 밖 소비의 1차 회수 경로는 수동 끄기다"를 명시하고, NFR-13 계측 이벤트에 "소진 판정 외 수동 끄기"를 추가한다(이 이벤트의 빈도가 편향의 크기다). §6.2의 "느려" 주장에 `[미검증]`을 붙인다.

### G-08 · 난이도·조리시간 분포의 활용 — **low**

**브리프** [§데이터 › 농정원 실측 분포]
> "난이도 초보환영 **50.8%** · … 조리시간 **30분 이하 65%** … 난이도와 조리시간 분포는 자취생 타깃에 잘 맞는다."

**PRD 현재** — 추천(FR-6~10)·레시피 상세 어디에도 난이도·조리시간이 필터·정렬·표시로 등장하지 않는다. 사용할지 말지 결정이 없다.

**착지** — §8 열린 질문("난이도·조리시간을 1차 레시피 카드에 표시할지, 필터로 쓸지") 또는 §5에 "1차 미사용" 명시.

### G-09 · 영양 수치 노출 여부 — **low**

**브리프** [§What Makes This Different 3 · §데이터]
> "영양 수치의 출처 관리" / "**영양 5종 100% 채움** — `Vision`의 영양 확장에 필요한 데이터가 이미 완비되어 있다."

**PRD 현재** — §5·NFR-10이 "영양 수치를 노출할 때는 출처가 있는 값만"이라는 **조건부** 문장만 둔다. 1차 레시피 상세에 열량·영양을 보일지 말지가 결정되지 않았다. 코퍼스 절반(농정원)은 열량만 있어 노출하면 결손 표시 규칙도 필요하다.

**착지** — 레시피 상세 FR(현재 없음 — FR-10이 유일한 상세 화면 요구)에 "영양은 1차 미노출" 또는 "식약처 5종만 출처 표기와 함께 노출"을 결정해 적는다.

### G-10 · `일품` 181건과 `RCP_PAT2` 실제 값 — **low**

**브리프** [§데이터 › 두 소스는 서로를 보완한다]
> "**상차림 역할**(반찬 574 · 일품 181 · 후식 142 · 밥 119 · 국찌개 103)" / "**일품 181건** — 한 그릇 요리는 자취생 타깃에 특히 잘 맞는다"

**PRD 현재** — FR-26이 브리프 addendum §1의 "실제 값: 밥 / 국·찌개 / 반찬 / 후식"을 그대로 받아 슬롯을 4값으로 적었다. **실측은 6값**이다(반찬 574 · 일품 181 · 후식 142 · 밥 119 · 국&찌개 103 · 기타 37 = 1,156). 브리프 본문과 addendum이 서로 달랐고 PRD가 틀린 쪽을 이어받았다. 자취생 타깃에 가장 맞는다고 브리프가 짚은 `일품`이 식단 구성 슬롯에서 사라졌다.

**착지** — FR-26 슬롯 정의를 실측 값으로 고치고, `일품`을 "단독 한 끼" 슬롯으로 둘지 결정. 1차 FR-7 계통 필터와 별개로 `일품` 필터를 둘지는 §8로.

### G-11 · "기호" 설정의 축소 — **low**

**브리프** [§Scope › 1차] "기호·알레르기 설정 — 개인화의 최소 단위" / [§The Solution] "현재 재고와 사용자 **기호**를 근거로"

**PRD 현재** — FR-5는 **제외 재료(비선호·알레르기)**만 다룬다. §3 "추천 — 재고·기호·이력을 근거로"라고 쓰지만 기호 = 제외 재료로 한정된 것이 어디에도 명시되지 않았다. 선호(계통 등)는 UJ-3 노트에서 "자주 해먹는 계통"으로 2차에 파생된다. 축소 자체는 타당해 보이나 §6.3에 없다.

**착지** — FR-5 설명에 "1차의 기호는 제외 재료로 한정한다. 양의 선호는 2차 FR-22에서 이력으로 파생"을 한 줄 추가.

### G-12 · 에이전트 하네스 포지셔닝 — **low · set aside**

**브리프** [addendum §5 › 이미 증명된 것]
> "에이전트 하네스는 신규 학습이 아니라 **CLI에서 웹 제품으로 이식하는 것**으로 포지셔닝한다."

**PRD 현재** — FR-26에 없음.

**착지** — **set aside.** 이것은 요구사항이 아니라 서술 각색이며, CLAUDE.md 규칙("각색이나 화법은 저장하지 않는다")에 따라 PRD에 넣지 않는 것이 맞다. `career-source.md`에 이미 있다면 그것으로 충분하다.

## 2. (b) 미인지 모순 — PRD가 브리프와 다르게 말하면서 §6.3에 적지 않은 것

### C-01 · 커버리지 정의에서 "1개 부족"이 빠졌다 — **high**

**브리프** [§Success Criteria › 기술 증명 지표 · §데이터 › 확인된 제약]
> "**재고 도달 가능 레시피 수** — 상비 재료만으로, **또는 1개만 추가하면** 만들 수 있는 레시피 수"
> "**정작 우려는 '1개 부족' 구간의 크기다** — 킬러 기능인 보완 재료 제안은 **딱 하나가 부족할 때만** 성립한다."

**PRD 현재** — §3 용어: "**커버리지**(도달 가능 레시피) — 상비 재료 21종(제외 목록 적용)**만으로 만들 수 있는** 레시피 수." 이것은 완전 매칭만이다. 그런데 SM-T3의 3.3% → 5.9%(56 → 100건)는 `measure_coverage.py`가 내는 값이고, **스크립트는 완전 + 1개 부족을 합산한다**(실행 확인: 정규화 전 완전 6 + 1개 부족 71 = 77건). 즉 PRD의 정의와 PRD의 수치가 서로 다른 것을 가리킨다. 더 중요한 것: 도달 가능의 **90% 이상이 1개 부족**인데 PRD는 1개 부족 건수를 **어디에도 보고하지 않는다.** FR-23 보완 재료 제안의 입력이 정확히 그 건수이고, 브리프 addendum §3이 남긴 사전 검증("하나만 사면 열리는 재료 상위: 쇠고기 5 · 깻잎 5 · …")의 현재 값(스크립트 출력: 오징어 4 · 깻잎 4 · 닭 3)도 인용되지 않았다.

**착지** — §3 정의를 "완전 매칭 + 1개 부족"으로 고친다. SM-T3에 완전/1개 부족 분해를 병기한다. FR-23에 "하나만 사면 열리는 재료" 현재 상위 값을 인용해 기능이 성립하는 구간의 크기를 적는다.

### C-02 · "RAG가 사는 자리"인데 질의가 없다 — **medium-high**

**브리프** [§Scope › 1차] "재료 기반 요리 추천 — RAG가 사는 자리" / [§Success Criteria] "RAG 검색 정확도 — 질의–정답 레시피 평가셋을 구축해 측정" / [§The Solution › 대화의 깊이] "단일 메뉴 추천에서 시작해 한 끼 식단 구성으로 넓어진다"

**PRD 현재** — §4.3 설명이 "RAG가 사는 자리다"를 이어받았지만, UJ-1과 FR-6~8이 정의하는 추천은 **표준명 완전 일치 하드 필터 + 계통 필터 + 최근 제외**로, 전부 결정적 집합 연산이다. 사용자가 자유 텍스트로 묻는 표면이 1차 여정에 없다. 그러면 SM-T4 "질의–정답 레시피 평가셋"의 **질의**가 무엇인지 정의되지 않고, §6.1 "RAG 증명"이 무엇으로 증명되는지 비어 있다. 브리프의 "대화" 프레임(대화의 깊이·영양 심화 대화)이 칩·목록 UI로 바뀐 것도 인지되지 않았다. 이것은 브리프 addendum §5가 "메워야 할 공백" 1순위로 꼽은 RAG 직접 구축과 직결된다.

**착지** — §8에 열린 질문 추가: "1차 추천에서 RAG가 하는 일(의미 검색·후보 랭킹·설명 생성 중 무엇)과 SM-T4의 질의 정의". FR-6 설명에서 "RAG가 사는 자리"를 그 답이 나오기 전까지는 `[미확정]`으로 표시.

### C-03 · FR-19 "자주 쓴 재료를 하향 가중" — 성공 정의와 반대 방향 — **medium**

**브리프** [§Success Criteria › 제품 성공의 정의]
> "한 문장에 제약과 목표가 함께 있다. **재료는 비슷하고, 음식은 다양하다.**" / "대파 한 단으로 세 가지를 만들었다면 …" / "**추천 랭킹에 다양성이 들어간다** — '가장 잘 맞는 레시피'가 아니라 **'최근에 만들지 않은 것 중 잘 맞는 레시피'**"

**PRD 현재** — FR-19: "최근 조리한 레시피와 **자주 쓴 재료를 하향 가중**해 추천 순서를 정한다." 브리프의 다양성은 **요리**의 다양성이고 재료는 **반복 사용**이 목표다(대파 3회가 성공 사례). 자주 쓴 재료를 내리면 아직 남아 있는 대파를 쓰는 요리가 밀린다 — 성공 정의의 앞 절을 훼손한다. 브리프가 의도한 것은 0회 재료(미사용)의 **상향**이며(G-01), 그것과 "자주 쓴 재료 하향"은 같은 말이 아니다.

**착지** — FR-19 문구를 "최근 조리 레시피 하향 + 사용 횟수 0인 재고 재료를 쓰는 레시피 상향"으로 고친다.

### C-04 · 판정불가 레시피의 코퍼스 잔류 — **medium**

**브리프** [§Scope › 지식베이스 분리]
> "**판정불가 3건** … **억지로 분류해 정답 세트에 남기면 정확도 수치 자체가 의미를 잃으므로, 코퍼스와 평가셋 양쪽에서 제외한다.**"

**PRD 현재** — §3 "판정불가 — 정답 세트에서 제외하고 별도 보고한다"(평가셋만). FR-7 A10: "판정불가로 분류된 레시피는 어느 계통을 골라도 나오지 않고, **'전체'에서만 나온다**" — 즉 코퍼스에 남긴다. 35건. 브리프는 코퍼스에서도 빼기로 했고 PRD가 유지로 바꿨는데 §6.3에 없다. PRD의 판정불가는 갈래 ②(과일주스·이유식)를 포함해 브리프의 3건과 성격이 다르므로, 바꾼 것이 맞더라도 그렇게 적어야 한다.

**착지** — §6.3에 한 행 추가("판정불가 코퍼스 제외 → '전체'에서만 노출, 근거: 갈래 ②는 계통 축이 없을 뿐 레시피로는 유효"). 갈래 ②의 이유식 계열이 자취생 타깃에 맞는지는 §8-16과 합쳐 판단.

### C-05 · "비율이 아니다"라면서 헤드라인이 비율 — **low**

**브리프** [§Success Criteria]
> "**커버리지를 비율이 아니라 절대 수로 재는 이유**: … 코퍼스를 키워도 비율은 오르지 않지만(오히려 떨어질 수 있다) 절대 수는 오른다."

**PRD 현재** — §3 커버리지 정의는 "요리 계통별 절대 수로 보고한다. 비율이 아니다"라고 브리프를 따르지만, SM-T3 헤드라인·§6.3·§8-17이 전부 "3.3% → 5.9%"를 앞세운다. FR-25 코퍼스 충전 뒤에는 브리프가 말한 대로 비율이 떨어질 수 있어 전후 비교가 비율로는 성립하지 않는다.

**착지** — SM-T3를 "56 → 100건(1,689 기준 3.3% → 5.9%)"으로 절대 수 우선 표기로 바꾼다.

## 3. (c) 수치 불일치 — 설명 없이 값이 다른 것

### N-01 · 동남아 건수 9 vs 15 — **medium**

**브리프** [§Scope › 지식베이스 분리] 농정원 실측 동남아 **6** · 식약처 추정 ~20.
**PRD** FR-7 "건수가 적은 계통(동남아 **9건**)", FR-25 "비한식 계통의 부족(동남아 9건)", SM-C4. 이 9는 **식약처 전량 분류 결과만**이다. 농정원 6을 더하면 병합 코퍼스의 동남아는 약 15건이다. PRD에는 두 소스를 합친 5종 분포표가 없다(FR-17은 식약처 1,156건만, SM-T3a는 농정원 계통만).

**착지** — FR-17에 병합 분포표(농정원 실측 + 식약처 전량 + 합계)를 넣고 FR-7·FR-25의 "9건"을 합계로 고친다.

### N-02 · 카테고리 정답 세트 84 vs 81 — **low**

**브리프** "원본의 서양·퓨전 **84건**은 재분류했다 — **81건 귀속, 3건 판정불가로 제외.** … 향후 자동 분류 파이프라인의 정답 세트로 쓴다."
**PRD** §3 "정답 세트 — 현재: … 카테고리 **84건** + 120건." 3건이 제외됐으므로 정답 세트 크기는 81이다(또는 "84건 중 81"). CLAUDE.md도 84로 적고 있어 같이 고칠 대상.

### N-03 · "주 3회 기준 약 N주치" 산식 — **low**

**브리프** "도달 가능한 서로 다른 요리는 **127건** — 주 3회 기준 약 **14주치**" (127 ÷ 3 ≈ 42주).
**PRD** §7.2 "100건 — 주 3회 기준 약 **11주치**" (100 ÷ 3 ≈ 33주).
두 문서가 같은 ÷9 산식을 쓴다. PRD가 브리프의 산술 오류를 그대로 이어받았다. 수치가 작을수록 "코퍼스가 부족하다"는 인상을 주므로 방향도 불리하다.

**착지** — §7.2 참고값을 "약 33주치(주 3회)"로 고치거나 산식을 명시.

### N-04 · 비사용자 임계 "재고 항목 50개" — **low**

**브리프** 1인 가구 냉장고 "항목이 **10~15개** 수준". 50이라는 값은 없다.
**PRD** §2.2 "재고 항목이 **50개**를 넘으면 이 제품의 재고 모델이 성립하지 않는다." 출처가 없고 `[ASSUMPTION]` 표시도 없다.

**착지** — §2.2에 `[ASSUMPTION]` 표시하고 §9에 등록.

### N-05 · 코퍼스 분모 1,693 / 1,689 / 1,661 — **low**

**브리프** 병합 후 이름 기준 고유 **1,661**종(중복 14), 측정 시 1,725건(고아 포함 573 + 1,152).
**PRD** §3·FR-15 코퍼스 **1,693**건(537 + 1,156). SM-T3의 분모는 스크립트 기준 **1,689**건(식약처 1,152). 식약처 4건이 측정에서 빠지는 이유(재료 파싱 실패 → `unparsed`?)와 중복 14건의 처리(G-05)가 적혀 있지 않아 세 값이 같은 코퍼스인지 알 수 없다.

**착지** — SM-T3 각주에 분모 1,689의 구성을 적고, FR-15 "현재" 수치와 다른 이유를 한 줄로.

## 4. 확인했지만 갭이 아닌 것 (기록용)

- 브리프 미해결 항목 중 PRD가 답한 것: 초기 재고 등록(FR-1·2), 추천 밖 소비 형식(FR-20 자연어), 전수 대조 주기(§8-12), 인분 스케일링(소멸), 식약처 분류(FR-17), 정규화 규칙(FR-16), 비정형 파싱(FR-15), 고아 38건(§8-13), 생성 검증(§8-9), 백엔드 스택(PRD addendum §1).
- 브리프 "넘지 말아야 할 선" 세 원칙 → FR-5·NFR-10 전부 반영.
- 제품 지표 세 개(재고 정확도·추천 수용률·재방문) → SM-3·4·5. 재고 정확도의 대리 지표 교체는 A15로 인지됨.
- 폐기 지표(평균 요리 가짓수 2.5) → PRD addendum §2.
- 라이선스 CC BY-SA 가정과 고지 → FR-18·NFR-11.
- 배제 소스(만개의레시피·RecipeNLG·크롤링·국외 데이터) → §5·PRD addendum §2. TheMealDB는 브리프 addendum §4 참조로 충분.
- 카테고리 추정 70%/23% → 실측 54.1%/34.2%: 625/1,156 · 395/1,156으로 재계산 일치.
- 코퍼스 충전 효율 2.9%, 식약처 재료 7.8개 vs 농정원 4.9개 → FR-25 근거로 암묵 반영, 수치 인용은 없지만 브리프 참조로 충분.

## 5. 처리 순서 제안

1. **C-01** — §3 커버리지 정의 한 줄 수정 + SM-T3 분해 병기. 정의와 수치가 어긋난 채로 아키텍처에 넘어가면 FR-23의 크기를 아무도 모른다.
2. **G-01 + C-03** — FR-22 항목 보강과 FR-19 방향 수정. 둘은 같은 뿌리(성공 정의의 "재료는 비슷하고")다.
3. **G-02** — NFR-14·SM-T5 추가. 포트폴리오 증명 축 하나가 통째로 빠져 있다.
4. **C-02** — §8 열린 질문 추가. 아키텍처가 RAG를 어디에 둘지 정하기 전에 PRD가 "무엇을 검색하는가"를 물어야 한다.
5. 나머지 medium(G-03~07, C-04, N-01)은 FR 결과 항목 한 줄씩. low는 문구 수정.
