# UX 설계 세션 — 시작 프롬프트

> 아래 내용을 새 세션의 첫 메시지로 그대로 붙인다. PRD 세션(2026-08-30~31)이 UX에 넘긴 결정을 한 곳에 모은 것이다.

---

`bmad-ux`를 실행해 PantryAI의 UX 스펙을 만든다. 나는 hj이고, 코칭 경로로 진행한다 — 화면과 흐름은 내가 결정하고 세션은 선택지와 근거를 정리한다.

## 입력 — 순서대로 읽는다

1. `_bmad-output/planning-artifacts/prds/prd-PantryAI-2026-08-18/prd.md` — **정본.** status: final. §0 "한눈에" → §2.3 여정 UJ-1~4 → §3 용어 → §4 기능 FR-1~27 → §8 열린 질문 순으로 읽는다.
2. 같은 폴더 `addendum.md` — 아키텍처 인계 사항과 버린 선택지. UX가 직접 쓰는 것은 §1 확정 사항 표.
3. `_bmad-output/planning-artifacts/briefs/brief-PantryAI-2026-08-13/brief.md` — 문제 정의와 성공 정의. **PRD §6.3에 적힌 것은 브리프가 뒤집혔으니 PRD를 따른다.**
4. `CLAUDE.md` — 작업 지침. 특히 의사결정 기록 규칙과 정직성 원칙.
5. `docs/career-source.md` — 읽기만. D-001~D-050. UX 결정에 트레이드오프가 생기면 여기에 D-051부터 기록하고 `python scripts/career_index.py`를 실행한다(`uv` 없음 — `python` 직접).

리뷰 파일(`review-*.md`, `reconcile-*.md`)은 읽지 않아도 된다. 필요하면 §8 항목 번호로 찾는다.

## 지켜야 할 것

- **용어는 PRD §3 그대로.** "차감"·"검수"·"카테고리"를 쓰지 않는다 — 소진 판정·소진 칩·요리 계통이다. 동의어를 만들지 않는다.
- **주인공은 지석**(28세·막 독립·원룸·퇴근길 지하철에서 첫 실행). 여정 UJ-1~4의 화면 순서를 바꾸지 않는다 — 채우기만 한다.
- **입력 비용이 제품의 전제다.** 역지표 SM-C1(재고 입력 터치 수·첫 등록 소요 시간)을 올리는 설계는 근거가 있어야 한다. 수량·분량·유통기한 입력 UI는 없다(FR-3).
- **재고에 맞지 않는 레시피는 뜨지 않는다**(UJ-4 원칙). 1개 부족 레시피는 목록에 섞이지 않고 재료 제안(FR-23) 구획으로만 보인다.
- 폼팩터는 **모바일 브라우저(반응형 웹)**로 가정한다(A1). 네이티브 앱 화면을 그리지 않는다.
- 보고서 톤으로 쓴다. 학습용 설명·코칭 화법을 산출물에 넣지 않는다.

## 하지 않는 것

- 2차·3차 기능(FR-19~22·24~26)의 화면. 통계 탭·자연어 소비 기록·전수 대조·식단 에이전트는 그리지 않는다.
- 기술 선택(스택·벡터DB·푸시 구현 방식). 아키텍처 몫이다. 웹 푸시로 충분한지는 §8-1에 남겨두고 UX는 "푸시가 온다"만 전제한다.
- PRD 결정의 재논의. FR을 바꿔야 한다고 판단되면 바꾸지 말고 `[NOTE FOR PRD]`로 표시해 넘긴다.
