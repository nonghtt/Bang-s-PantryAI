# PantryAI — 재료명 정규화 전량 실행 (2단계 정제) 작업 지시

> 이 파일을 별도 세션에 그대로 붙여넣는다. BMAD는 로드하지 않는다.
> **분할 실행이다.** 한 세션에서 전량을 하지 않는다. 배치 단위로 실행하고 이어서 한다.

---

## ⚠️ 먼저 읽을 것 — 이 작업은 측정 대상이다

결과는 정답 세트와 대조해 일치율로 채점된다. 다음 파일을 **절대 열지 않는다.**

| 열지 말 것 | 이유 |
| --- | --- |
| `data/labels/ingredient_standard_answers.csv` | **정답지다.** 보면 측정이 무의미해진다 |
| `data/labels/context_dependent_rows.csv` | 행 단위 정답지 |
| `data/labels/archive/` | 정답지의 이전 버전 |
| `data/labels/ingredient_dictionary_draft.csv` | 규칙이 만든 부분 정답 |
| `data/labels/stage2_pilot_output.csv` 및 `.score.md` | 파일럿 산출물과 채점 결과 |
| `scripts/score_normalization.py` | 채점 스크립트 |

**채점하지 않는다.** 산출물만 만들고 끝낸다. 채점은 분리된 시점에 수행한다 —
지금 채점하면 결과를 보고 프롬프트를 고치게 되고, 그 순간 측정이 오염된다.

실수로 열었다면 **숨기지 말고 보고한다.** 오염된 수치를 모르고 쓰는 것이 훨씬 나쁘다.

---

## 배경

PantryAI는 사용자의 냉장고 재고를 기준으로 요리를 추천하는 서비스다.
레시피 코퍼스는 1단계 정제를 마쳐 두 공공 API가 같은 스키마로 통합돼 있으나,
**재료명이 원본 표기 그대로다.** 같은 재료가 여러 이름으로 흩어져 있다.

```
마늘 347행 · 다진마늘 282행 · 다진 마늘 151행 · 마늘다진것 36행 · 통마늘 11행
달걀 168행 · 계란 111행
```

사용자가 `마늘`을 재고에 넣었을 때 `다진마늘`을 요구하는 레시피가 매칭되지 않으면
추천이 통째로 사라진다. **이 작업은 각 재료 행에 표준명을 배정하는 것이다.**

수행 시점은 **빌드 시점 일괄 배치**로 확정돼 있다. 실행 시점에 도는 작업이 아니므로
레시피 맥락(요리명·조리과정)을 함께 보고 판단해도 된다 — 오히려 그러라고 이 시점을 골랐다.

**파일럿 50건은 이미 끝났고 일치율 99.2%가 나왔다.** 이번은 전량 1,693건이다.
파일럿에 포함됐던 50건도 다시 포함된다 — 그 사이 표준명이 3건 바뀌었고(`건고추` 신설,
`깨소금`·`실고추` 독립), 같은 기준으로 다시 만드는 편이 안전하기 때문이다.

`data/raw/`는 읽지 않는다.

## 분할 실행 방법

### 1. 먼저 진행 상황을 본다

```bash
python scripts/merge_batches.py --status
```

배치 12개(각 레시피 114~176건 / 재료 약 1,600행)의 실행 여부가 나온다.
**미실행 배치 중 가장 앞 번호부터** 진행한다.

### 2. 한 세션에서 배치 하나를 처리한다

`batches.txt`에서 해당 `batch_id`의 레시피만 골라 작업한다.
여유가 있으면 다음 배치를 이어서 해도 되지만, **배치를 반쯤 하다 멈추지 않는다.**
중간에 끊길 것 같으면 그 배치를 시작하지 않는다.

### 3. 배치마다 파일 하나를 쓴다

```
data/labels/batches/stage2_batch-01.csv
data/labels/batches/stage2_batch-02.csv
...
```

**한 배치는 한 파일에 전량 들어가야 한다.** 이어쓰기로 나누지 않는다.

### 4. 전 배치가 끝나면 병합한다

```bash
python scripts/merge_batches.py
```

중복 키·행 수 불일치·원본에 없는 행·어휘 밖 표준명을 검사하고,
어긋나면 **병합하지 않고 멈춘다.**

## 정규화 규칙

**`data/labels/README.md`를 읽고 그대로 따른다.** 요약을 옮기지만 충돌하면 README가 우선한다.

핵심 판정 기준은 하나다.

> **재고에 A가 있을 때, B를 요구하는 레시피를 실제로 만들 수 있는가?**

| 축 | 처리 |
| --- | --- |
| 가공 상태 (다진·채썬·즙·간 것) | **통합** — 사용자가 직접 할 수 있다 |
| 부위 (등심·안심) | **통합** — 가정에서 구분하지 않는다 |
| 품종 (대파/실파, 표고/팽이, 홍고추/청양고추) | **구분** |
| 조리 단계 차이 (쌀/밥) | **통합** |
| 결과물이 달라지는 차이 (화이트와인/레드와인) | **구분** |
| **건조** | **원물이 통상 생물이면 구분**(표고버섯·고추·새우·다시마), **원물이 통상 건조로 유통되면 통합**(미역·당면·소면) |

판단이 애매하면 **같은 레시피에 두 이름이 함께 나오는지** 본다. 함께 나오면 작성자가 구분했다는 뜻이다.
다만 **함께 안 나온다고 같은 물건은 아니다** — 한 요리에 두 종류의 김치를 넣을 일이 없어 0이 나올 뿐이다.

### 맥락을 볼 때 — 오탐 두 가지를 조심한다

조리과정이 재료명보다 자세한 경우가 있다. `표고버섯`이라고만 적혔는데 조리과정이
`"말린 표고버섯"` 또는 `"물에 불려"`라고 하면 그 행은 `건표고버섯`이다
(생표고는 불리지 않는다). **다만 다음 두 경우는 아니다.**

```
① 같은 레시피에 수식어 붙은 재료 행이 따로 있으면, 이 행은 기본형이다
   통삼겹스테이크    재료에 로즈마리(2g) + 건로즈마리(1g) 둘 다 존재
   → 조리과정 "건로즈마리와 로즈마리를 넣고" 는 두 재료를 말하는 것

② 수식어와 대상 사이에 다른 재료명이 끼면, 그 재료를 수식하는 것이다
   "감자와 표고버섯은 채 썰고, 불린 곤드레나물은 잘게 썬다"
   → 불린 대상은 곤드레나물이지 표고버섯이 아니다
```

### 어휘 제약

**`standard_names.txt`의 352종 안에서만 고른다.** 마땅한 이름이 없으면
`name_raw`를 그대로 쓰고 `근거`를 **`어휘없음`으로 시작**하게 적는다.
판단이 안 되면 추측하지 말고 **`판별불가`로 시작**하게 적는다. **새 이름을 지어내지 않는다.**

## 하지 말 것

- **정답지를 열지 않는다** (위 표 참조)
- **채점하지 않는다.** 일치율을 계산하려 시도하지 않는다
- `name_raw`를 수정하지 않는다
- `data/processed/`의 어떤 파일도 수정하지 않는다
- 어휘 밖의 표준명을 만들지 않는다
- 재료 행을 추가·삭제·병합하지 않는다
- 수량(`qty_raw`) 해석·단위 통일을 하지 않는다 — 이 작업 범위가 아니다
- 카테고리 분류·주재료 판정·중복 레시피 판정을 하지 않는다
- **배치를 반쯤 하다 멈추지 않는다**

## 검증 요구사항

배치 파일을 쓰기 전에 스스로 확인한다.

| 검사 | 기준 |
| --- | --- |
| 행 수 | 그 배치의 재료 행 수와 정확히 일치 |
| 키 보존 | `(source, source_id, seq)` 조합이 입력과 정확히 일치, 중복 없음 |
| `name_raw` 보존 | 입력과 문자열이 완전히 같다 |
| 어휘 준수 | `표준명`이 전부 어휘 안에 있다 (`어휘없음`·`판별불가` 표시분 제외) |
| 공란 | `표준명`·`근거` 공란 0 |

**어긋나면 파일을 쓰지 말고 멈춘다.** 쓴 뒤에는 `python scripts/merge_batches.py --status`로
그 배치가 `완료`로 뜨는지 확인한다.

## 배치마다 보고할 것

산출물과 별개로, 대화에서 다음을 알려준다.

1. **레시피당 평균 투입 토큰** — 파일럿에서 받지 못한 값이다. **남은 배치의 비용 추정에 쓰인다**
2. **판별불가 / 어휘없음으로 남긴 행** — 몇 행이고 어떤 재료명인가
3. **맥락이 판단을 바꾼 횟수** — 이름만 봤을 때와 다른 답이 나온 경우
4. **오탐 검사에 걸린 건수** — 위 ①②에 해당해 기본형으로 되돌린 경우
5. **규칙이 모호했던 지점** — README를 읽고도 갈렸던 케이스

3·4가 특히 중요하다. **맥락을 보는 설계가 값을 하는지, 오탐 검사가 실제로 필요한지**를 이 수치로 판정한다.

## 작업 방식

1. `python scripts/merge_batches.py --status` 로 미실행 배치를 확인한다
2. `data/labels/README.md`와 `standard_names.txt`를 읽는다
3. 가장 앞 번호의 미실행 배치를 고르고, 그 레시피의 재료·조리과정을 모은다
4. **레시피 단위로** 판단한다 — 재료 목록과 조리과정을 함께 놓고 본다
5. 검증 5항목을 통과하면 `data/labels/batches/stage2_batch-NN.csv`를 쓴다
6. `--status`로 확인하고, 위 5가지를 보고한다

**결과를 좋게 만들려고 규칙을 바꾸지 않는다** — 규칙이 이상하면 그 사실을 보고한다.
