# 2단계 정규화 — 전량 산출물 채점 지시서

## 이 세션이 하는 일

**채점하고 측정한다. 산출물은 고치지 않는다.**

전량 정규화 실행은 끝났다. 이 세션의 산출은 새 라벨이 아니라 **수치**다.

---

## 배경 (읽고 시작한다)

- `data/labels/stage2_full_output.csv` — 재료 **18,988행** 전량에 표준명이 배정돼 있다. 12배치로 나눠 실행한 뒤 `scripts/merge_batches.py`로 병합했고, 병합 검사(행 수·중복 키·원본에 없는 행·어휘 밖 표준명·공란)를 전부 통과했다.
- **실행 세션은 정답지·사전 초안·채점 스크립트를 한 번도 열지 않았고, 채점도 하지 않았다.** 이것이 D-034(정규화 측정의 실행 격리)의 설계다. 결과를 보고 규칙을 고치면 측정이 오염되기 때문이다.
- **그 격리를 유지하는 유일한 방법은 채점 세션이 산출물을 수정하지 않는 것이다.** 채점 후 산출물을 손보면 격리는 사라지고 수치는 자기 채점이 된다.

관련 결정: `docs/career-source.md`의 D-034 · D-035(파일럿 채점) · D-036(건조 정책·행 단위 정답) · D-037(커버리지 재측정) · D-038(분할 설계) · D-039 · D-040.

---

## 절대 하지 않는 것

1. **`data/labels/stage2_full_output.csv`와 `data/labels/batches/*.csv`를 수정하지 않는다.** 일치율이 낮아도 고치지 않는다. 낮으면 낮은 대로 기록한다.
2. **점수를 올리려고 정답지를 고치지 않는다.** 정답지(`ingredient_standard_answers.csv`, `context_dependent_rows.csv`)가 틀렸다고 판단되면 **고치기 전에 근거를 제시하고 사용자에게 확인받는다.** 파일럿에서 실제로 정답지 결함 2건이 나왔으므로(D-035) 가능성은 열려 있지만, **판정 주체가 정답지를 만든 쪽이라는 사실을 반드시 기록에 남긴다.**
3. **채점 스크립트를 결과에 맞춰 고치지 않는다.** 진짜 버그면 고치되, **왜 버그인지를 먼저 문장으로 적고** 고친다.
4. `data/raw/`·`data/processed/`는 읽기 전용이다.
5. 행 수 검사·잔차 검사를 우회하지 않는다. 어긋나면 채점하지 않고 멈추는 것이 정상 동작이다.

## 작업

### 0. 산출물을 먼저 고정한다 (권장)

`data/labels/stage2_full_output.csv`와 `data/labels/batches/`는 아직 커밋되지 않았다. **채점 전에 커밋한다.** 그래야 "채점 결과를 보고 산출물을 고치지 않았다"가 증명 가능한 사실이 된다.

### 1. 채점

- `scripts/score_normalization.py`의 인터페이스를 먼저 읽는다. 파일럿(`stage2_pilot_output.csv`) 기준으로 만든 스크립트라 경로가 고정돼 있을 수 있다. 그러면 **입력 경로를 인자로 받게만 고친다 — 채점 로직은 건드리지 않는다.**
- 행 단위 정답(`context_dependent_rows.csv`, 23건)이 이름 단위 정답보다 **우선 적용**되는지 확인한다(D-036에서 그렇게 고쳤다).
- 결과를 `data/labels/stage2_full_output.csv.score.md`로 남긴다.

### 2. 보고할 수치

| 항목 | 왜 필요한가 |
| --- | --- |
| 전체 일치율 | 공식 수치 |
| 채점 가능 행 수·비율 | 정답지 밖 행은 채점되지 않는다. 분모를 숨기지 않는다 |
| 판정 유형별 정확도 (그대로·표기·가공·제외) | 어느 판정이 약한가 |
| 행 단위 정답 23건의 적중 | 맥락 판정이 실제로 맞았는가 |
| **배치별 일치율** | D-038 한계 ②: 배치가 12개로 쪼개져 판단이 흔들렸는지는 여기서만 보인다 |
| **출처별 일치율** (식약처 / 농정원) | D-039의 출처 격차가 정확도에서도 나타나는가 |
| 불일치 상위 재료명 | 어디를 고쳐야 하는가 |
| 어휘없음 581행·판별불가 53행이 정답지에 있었는가 | 모르겠다고 표시한 것이 실제로 몰라도 되는 것이었는가 |

### 3. 불일치 분석

불일치를 세 갈래로 나누고 각 건수와 대표 사례를 적는다.

- **(a) 산출물이 틀림** — 규칙은 명확한데 잘못 배정했다
- **(b) 정답지가 틀림** — 근거를 적는다. 자기 채점임을 명시한다
- **(c) 규칙 문서가 모호** — `data/labels/README.md`가 판단을 결정해주지 못한 지점

**(a)와 (b)를 합산한 수치를 공식 일치율로 쓰지 않는다.** 파일럿에서 98.4%(공식)와 "모델 오류 0건"(해석)을 분리해 기록한 것과 같은 기준이다.

### 4. 커버리지 재측정

`python scripts/measure_coverage.py`

지금까지의 "정규화 후 5.3%"는 **추정치**다 — 파일럿 49건만 실제 산출물이고 나머지 1,640건은 이름 단위 매핑으로 대체한 값이었다(D-037 한계 ②). 이제 전량 실제 산출물로 다시 잰다. 스크립트가 `stage2_full_output.csv`를 입력으로 받도록 바꿔야 할 수 있다 — **측정 방법(재고 21종·제외 70종·매칭 방식)은 바꾸지 않는다.** 그래야 차이가 정규화 효과가 된다.

비교 대상(같은 스크립트로 잰 값):

| 지점 | 값 |
| --- | --- |
| 정규화 전 · 정확 일치 | 3.3% (56건) |
| 정규화 전 · 부분문자열 | 4.6% (77건) |
| 정규화 후 · **추정** | 5.3% (90건) |
| 정규화 후 · **실측** | ← 이번에 잰다 |

### 5. 기록

CLAUDE.md 규칙대로 `docs/career-source.md`에 남기고 **`python scripts/career_index.py`를 실행한다.** 다음 ID는 **D-041**이다.

이번 채점으로 갱신될 것이 두 개 있다.

- **D-039** `verified: yes` — 맥락이 판단을 바꾼 36건이 실제로 옳았는지는 지금 미검증이다. 행 단위 정답 적중이 그 답이다
- **D-040** — 검사에 걸린 오탐 4건 말고, **검사를 통과했지만 틀린 오탐**이 채점에서 드러날 수 있다

기록 대상은 "일치율이 몇 %였다"가 아니라 **판단이 갈렸던 지점**이다. 수치만 나오고 트레이드오프가 없었다면 기존 항목의 `결과`를 갱신하는 것으로 충분하다.

## 참고 — 채점 대상 산출물의 알려진 성질

| 항목 | 값 |
| --- | --- |
| 행 | 18,988 (식약처 13,047 · 농정원 5,941) |
| 레시피 | 1,689 (배치 명세 1,693건 중 4건은 재료 행 0개) |
| 고유 재료명 | 1,966종 → 표준명 802종 |
| 어휘 안으로 배정 | 18,354행 (96.7%) |
| 어휘없음 | 581행 (414종, 3.1%) — `name_raw` 그대로 보존 |
| 판별불가 | 53행 (37종, 0.3%) |
| 어휘 사용 | 표준명 352종 전부 사용 |

실행 세션이 보고한 다섯 가지:

1. **투입 토큰** — 배치 02~12 실측 평균 약 600토큰/레시피
2. **판별불가·어휘없음** — 위 표. 어휘 결손율이 출처별로 갈림(식약처 최신분 6.7% vs 농정원 2.4%), 단일 최대 결손은 `치즈` 계열
3. **맥락이 판단을 바꾼 횟수** — 36건 (0.19%). 식약처 15/13,047(0.11%) vs 농정원 21/5,941(0.35%). 36건 중 26건이 `표고버섯`→`건표고버섯`
4. **오탐 검사에 걸린 건수** — 4건, 유형 4가지 각 1건 (수식어 붙은 행 동시 존재 / 다른 재료명이 끼어듦 / 수식어가 도구에 붙음 "마른 행주" / 건조 동사가 조리 결과를 가리킴 "햇볕에 말린다")
5. **규칙이 모호했던 지점** — 약 40개의 접기 관례를 세션이 스스로 정해 적용했다. README에서 유도되지 않은 것이 다수이며, 위 (c) 분류에서 다시 드러날 것이다
