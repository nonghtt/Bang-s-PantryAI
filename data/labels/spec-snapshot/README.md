# 명세 스냅샷 — 분류 실행 시점 고정본

`category_full_output.csv`를 만든 실행 세션이 **실제로 읽은** 명세다.
산출물 고정 커밋 `2854bd2` 시점에서 뽑았다.

## 왜 스냅샷이 필요한가

채점기는 명세에 요리명이 그대로 등장하는 행을 분리한다(`category_README.md` §4-4).
그런데 **현재 문서를 읽으면 채점 이후에 추가된 내용까지 분리 대상이 된다.**

실제로 사고가 났다. 채점 결과를 규칙 문서에 기록하면서 불일치 사례
(`고등어구이`·`무말랭이김치`·`연근샐러드, 흑임자소스`)를 적었더니,
**그 3행이 다음 채점에서 자동으로 빠져 대표 층이 92.9% → 100%가 됐다.**
분리 장치가 사후 문서화에 소급 적용되어 **불일치를 숨긴 것이다.**

**실행 세션이 본 명세는 그 시점의 것이지 지금 것이 아니다.** 그래서 고정한다.

## 규칙

- 이 폴더는 **읽기 전용이다.** 손으로 고치지 않는다
- 다음 라운드를 돌리면 그 시점 커밋에서 다시 뽑아 교체한다
- 채점기는 이 폴더가 있으면 여기를, 없으면 현재 문서를 읽고 **경고를 낸다**
