# PantryAI — 요리 계통 분류 전량 실행 작업 지시

> 이 파일을 별도 세션에 그대로 붙여넣는다. BMAD는 로드하지 않는다.
> **분할 실행이다.** 한 세션에서 전량을 하지 않는다. 배치 단위로 실행하고 이어서 한다.

---

## ⚠️ 먼저 읽을 것 — 이 작업은 측정 대상이다

결과는 정답 세트와 대조해 정확도로 채점된다. 다음 파일을 **절대 열지 않는다.**

| 열지 말 것 | 이유 |
| --- | --- |
| `data/labels/category_answers.csv` | **정답지다.** 보면 측정이 무의미해진다 |
| `data/labels/category_sample.txt` | **표집 명세.** 어느 레시피가 채점되는지 알면 거기만 잘하게 된다 |
| `scripts/sample_categories.py` | 표집 로직과 키워드 목록. 위와 같은 이유 |
| `_bmad-output/planning-artifacts/briefs/brief-PantryAI-2026-08-13/recipe-category-mapping.json` | 농정원 84건의 재분류 정답 |
| `docs/career-source.md` | 판단 근거가 전부 적힌 결정 기록 |
| `scripts/score_categories.py` (생기면) | 채점 스크립트 |

**채점하지 않는다.** 산출물만 만들고 끝낸다. 정확도를 계산하려 시도하지 않는다 —
지금 채점하면 결과를 보고 판단 기준을 고치게 되고, 그 순간 측정이 오염된다.

실수로 열었다면 **숨기지 말고 보고한다.** 오염된 수치를 모르고 쓰는 것이 훨씬 나쁘다.

## 배경

PantryAI는 사용자의 냉장고 재고를 기준으로 요리를 추천하는 서비스다.

추천할 때 **요리 계통을 선택해 그 범위 안에서만 검색**할 수 있어야 한다. 그러려면 레시피마다
계통이 붙어 있어야 하는데, **식약처 1,156건에는 그 필드가 아예 없다.**

요리명 키워드로 때우려 했더니 안 됐다. 식약처 1,156건에 외래 계통 키워드를 걸면 359건(31.1%)이
걸리는데 **눈으로 보면 대다수가 한식이다.** 이 작업이 필요한 이유이고, 동시에
**카테고리 자동 분류 정확도** 지표가 측정할 대상이다.

**한 레시피에 계통 하나를 배정한다. 그게 전부다.** 재료명 정규화·주재료 판정·중복 판정은
이 작업의 범위가 아니다.

## 입력 파일

| 파일 | 내용 |
| --- | --- |
| `data/processed/recipes.json` | 레시피 기본정보. `name`·`ty_nm`·`rcp_pat2`·`rcp_way2`·`summary`·`hash_tag` |
| `data/processed/recipe_ingredients.json` | 재료 행. `(source, source_id, seq, name_raw, qty_raw, role_raw)` |
| `data/processed/recipe_steps.json` | 조리 과정. `(source, source_id, step_no, description)` |
| **`data/labels/category_README.md`** | **분류 규칙.** 사람이 정답 세트를 만들 때 따른 것과 같은 규칙이다 |
| **`data/labels/category_batches.txt`** | **배치 명세.** `batch_id<TAB>source<TAB>source_id<TAB>요리명` |

`data/raw/`·`data/processed/`는 **읽기 전용이다.**

> **농정원의 `nation_nm`은 봐도 된다.** 원천이 붙인 계통이고, 규칙 문서 §3-2·§3-3의 표가
> 그것을 집계한 것이다. 다만 **원천 라벨에도 오류가 있다**(`카레라이스 → 동남아`).
> 참고 자료이지 정답이 아니다. 그리고 **분류 대상인 식약처에는 이 필드가 없다.**

## 분할 실행 방법

대상은 **식약처 1,156건**이다. 농정원 537건은 원천에 계통이 있어 대상이 아니다.

### 1. 먼저 진행 상황을 본다

```powershell
$env:PYTHONIOENCODING = 'utf-8'
python scripts/category_batches.py --status
```

`미실행`인 것 중 **가장 앞 번호** 하나를 고른다.

### 2. 한 세션에서 배치 하나를 처리한다

배치는 8개이고 각 144~145건이다. **한 배치를 끝내면 멈춘다.** 여유가 있으면 다음 배치를
이어서 해도 되지만, **배치를 반쯤 하다 멈추지 않는다.**

### 3. 배치마다 파일 하나를 쓴다

`data/labels/category_batches/category_batch-NN.csv`

### 4. 전 배치가 끝나면 병합한다

```powershell
python scripts/category_batches.py
```

행 수·중복 키·명세 밖 행·빠진 행·요리명 변경·카테고리 값·`sub` 허용 범위·근거축 값·공란을
검사하고 **어긋나면 병합하지 않고 멈춘다.** 이 검사를 우회하지 않는다.

## 분류 규칙

**`data/labels/category_README.md`를 읽고 그대로 따른다.** 아래는 요약이며,
**충돌하면 문서가 우선한다.**

### 카테고리 5종

`한식` · `중식` · `일식` · `동남아` · `양식` — 모두 동등한 위계다.

5종에 정확히 맞지 않는 계통은 **가장 가까운 칸에 넣되 원 국가를 `sub`에 남긴다.**
프랑스·이탈리아·스페인·독일 → `양식` + `sub`. 인도(버터치킨·탄두리·마살라) → `동남아` + `sub: 인도`.

### 기본 원칙

> **요리의 형태·조리법이 어느 계통인가로 판단한다. 재료의 국적이 아니다.**

`토마토`가 들어갔다고 양식이 아니고 `치즈`가 들어갔다고 양식이 아니다.

### 판정 순서

1. **요리명이 계통을 직접 말하는가** — `중국식볶음밥`·`유부초밥`
2. **조리법이 계통을 말하는가** — 튀겨 소스에 버무림·초밥 형태·파스타 삶기
3. **주재료 구성이 계통을 말하는가** — 고추장·된장·김치 기반 / 커리페이스트·피시소스·레몬그라스 기반. **코코넛밀크 하나로 동남아를 정하지 않는다** (문서 §3-5)
4. **위 셋이 충돌하면 `판정불가`** — 억지로 배정하지 않는다

**어느 단계에서 판단이 났는지를 `근거축` 컬럼에 적는다** (`요리명`·`조리법`·`주재료`).

### 이름 안의 외래어에 끌려가지 않는다

**한국 음식이 흡수해 일반 명사가 된 어휘가 있다.** `완자`·`주먹밥`·`전골`은 한식 어휘이고
중식·일식 신호가 아니다. 반대로 `탕수`(중식)·`초밥`·`우동`(일식)·`파스타`·`크림소스`(양식)는
계통이 유지된다.

**그릇의 이름은 계통을 정하지 않는다. 무엇을 담았는가가 정한다** — `볶음밥`·`덮밥`·`샐러드`·`만두`.

`카레`·`커리`는 **계통 신호가 아니다.** 나머지 요소로 판단한다 — 이름의 나머지, 조리법,
함께 쓰인 양념 구성이다. **동남아로 보내는 기준은 문서 §3-5를 반드시 읽는다.**

### `판정불가`

**5종 중 하나로 귀속할 수 없을 때만 쓴다.** 두 갈래다 — **① 충돌**(둘 이상이 대등하게
섞여 어느 쪽도 주가 아니다) **② 신호 없음**(주스·이유식처럼 계통이라는 축이 적용되지 않는다).

**모르겠으면 쓰는 칸이 아니다.** 형태가 서양 디저트로 확립된 것(푸딩·판나코타·머핀)은
②가 아니라 `양식`이다.

억지로 분류해 넣는 것도, 애매하다고 남발하는 것도 수치를 망친다.

- 레시피를 추가·삭제·병합하지 않는다

- 재료명 정규화·주재료 판정·중복 레시피 판정을 하지 않는다

## 배치마다 보고할 것

산출물과 별개로, 대화에서 다음을 알려준다. **이 수치가 설계 판단의 근거가 된다.**

1. **레시피당 평균 투입 토큰** — 남은 배치의 비용 추정에 쓰인다
2. **`판정불가`로 남긴 건수와 요리명** — 이 비율이 높으면 5종 체계가 코퍼스에 맞지 않는다는 신호다
3. **근거축 분포** — `요리명`·`조리법`·`주재료`가 각각 몇 건인가. **규칙의 판정 순서가 실제 데이터와 맞는지를 이 수치로 검증한다**
4. **요리명만 봤다면 다르게 판정했을 건수** — 재료·조리과정을 읽고 답이 바뀐 경우. **재료·조리과정까지 읽는 설계가 값을 하는지를 이 수치로 판정한다.** 대표 사례 3건을 함께 적는다
5. **`판정불가` 직전까지 갔지만 한쪽으로 정한 건수** — 어디가 아슬아슬했는가
6. **규칙이 모호했던 지점** — 문서를 읽고도 갈렸던 케이스. 규칙에서 유도되지 않아 스스로 정한 관례가 있으면 **그 목록을 남긴다**

3·4가 특히 중요하다. 재료명 정규화에서 같은 항목을 고정해 받은 결과가 설계 판단을 여러 번
바꿨다 — 예고한 것과 실측이 달랐다.

## 작업 방식

1. `python scripts/category_batches.py --status` 로 미실행 배치를 확인한다
2. `data/labels/category_README.md`를 읽는다
3. 가장 앞 번호의 미실행 배치를 고르고, 그 레시피의 **기본정보·재료·조리과정을 함께** 모은다
4. **레시피 단위로** 판단한다 — 요리명만 보고 정하지 않는다
5. 검증 7항목을 통과하면 `data/labels/category_batches/category_batch-NN.csv`를 쓴다
6. `--status`로 확인하고, 위 6가지를 보고한다

**결과를 좋게 만들려고 규칙을 바꾸지 않는다** — 규칙이 이상하면 그 사실을 보고한다.
